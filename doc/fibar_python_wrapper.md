# FIBAR Python Wrapper

The Python API lives under `event_vision_utils.recon`. Its native module is
generated by gtwrap from `wrap_interfaces/fibar_reconstructor.i`; event arrays and
image/patch results cross the boundary as Eigen vectors and matrices.

## Build

From the repo root:

```bash
git submodule update --init lib/fibar_lib lib/wrap
./build_lib.sh --python
```

The native extension is optional for package import. If it is missing,
`fibar_native_available()` returns `False` and reconstruction example demos write
a blocked summary instead of failing with an import traceback.

The generated module is
`eklt_rebuild.CFibarReconstructorAdapter`. The
`event_vision_utils.recon.CFibarReconstructor` API remains the public
orchestration layer and performs NumPy dtype normalization before calling the
adapter.

## Relocatable package

After building the wrapper, create the unified `eklt-rebuild` platform wheel
from the `python/` directory:

```bash
python3.12 -m pip wheel --no-build-isolation --no-deps \
  --wheel-dir build/wheels python
```

The shared wheel co-locates only `eklt_rebuild.so` and
`libeklt-rebuild.so`; the static wheel contains only the generated extension.
The Linux runtime paths use `$ORIGIN`, and the package excludes
`_wrapper_build.py`, which is source-checkout metadata containing absolute
build paths. A wheel must therefore be validated after moving it away from the
build tree and with `LD_LIBRARY_PATH` unset.

`./build_lib.sh --python --install` applies the same layout below
`<build-dir>/install/lib/python3.12/site-packages/eklt_rebuild`; it does not
write to the workstation's active Python environment.

## Usage

```python
from event_vision_utils.recon import CFibarReconstructor, SFibarConfig

reconstructor = CFibarReconstructor(SFibarConfig(width=200, height=200))
reconstructor.accept_events(x, y, p, t_us)
image = reconstructor.request_image(int(t_us[-1]))
patch = reconstructor.request_patch(50, 50, 5, int(t_us[-1]))
```

Arrays are:

- `x`, `y`: integer coordinates,
- `p`: signed polarity `-1` or `+1`,
- `t_us`: monotonic timestamps in microseconds.

NumPy inputs may be non-contiguous. They are normalized and copied into
double-precision Eigen vectors at the wrapper boundary, then validated and
converted to the core's exact integer types by
`CFibarReconstructorAdapter`.

## Example Demo

```bash
scripts/run_elope_reconstruction_example_demo.sh \
  --input /path/to/official_elope_sequence.npz \
  --output-dir outputs/elope_reconstruction
```

The loader honors complete scalar geometry metadata when present. Official
ELOPE files omit those fields and therefore use the dataset's documented
200-by-200 sensor. The event-preview video uses 10 ms bins at 100 frames per
second. The patch diagnostic defaults to a 1200-by-800 frame: an enlarged
800-by-800 event panel beside eight 200-by-200 patches in a 2-by-4 mosaic.
Accepted and rejected patches have distinct borders and each tile identifies
its candidate coordinate, valid fraction, and gradient energy.

Adjust the bounded patch layout when a different diagnostic size is useful:

```bash
scripts/run_elope_reconstruction_example_demo.sh \
  --input /path/to/official_elope_sequence.npz \
  --output-dir outputs/elope_reconstruction \
  --patch-panel-size 800 \
  --patch-columns 2 \
  --patch-max-candidates 8 \
  --max-patch-quality-samples 50000
```

Reconstruction and patch frames are streamed separately. The immutable event
array is replayed through a fresh reconstructor for the patch pass so neither
complete video is retained in RAM. Patch-quality plotting retains at most the
explicit sample limit while reporting both retained and total inspected
counts.

Expected artifacts:

- `summary.json`
- `events_preview.mp4`
- `reconstruction.mp4`
- `fibar_patches.mp4`
- `plots/event_rate.png`
- `plots/event_stream_3d_views.png`
- `plots/patch_quality.png`

The event-rate and patch-quality plots use Matplotlib with visible titles,
subtitles, tick scales, and unit-bearing axes. The six-view event cloud labels
both projected coordinates in every view and distinguishes positive and
negative polarity by marker shape as well as color.

The complete ROS2 ELOPE pipeline additionally writes
`tracking/eklt_tracks.mp4`. It overlays stable per-track colored dots on 10 ms
event windows at 4x sensor resolution. The color and coordinate rules match
the native ROS-free feature renderer. Recent observations are held for a
bounded 100 ms so tracker updates remain visible between video frames.

The complete JSON, track-text, plot, video, reader, and cleanup contracts are
defined in
[`Single-Sequence ELOPE Artifact Contract`](elope_single_sequence_pipeline.md).
