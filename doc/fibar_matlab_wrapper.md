# `eklt_rebuild` MATLAB R2024b Wrapper

The MATLAB binding is generated by the pinned `lib/wrap` checkout from the same
gtwrap interface as Python and links the canonical `libeklt-rebuild` target.
The generated module uses the identifier-safe `eklt_rebuild` spelling required
by MATLAB and C++, while the published native library retains `eklt-rebuild`.

Arrays use Eigen-backed `gtsam::Vector` and `gtsam::Matrix` aliases. Conversion,
validation, and reconstruction remain in the native `wrap_adapters` boundary;
there is no MATLAB-only C++ wrapper hierarchy.

## Build and test

```bash
git submodule update --init lib/fibar_lib lib/wrap
./build_lib.sh \
  --build-dir build/matlab-wrapper \
  --type Release \
  --matlab \
  --define WARNINGS_ARE_ERRORS=ON
```

The ordinary CTest run starts R2024b with the required system-runtime preload
and covers reconstruction, invalid-batch recovery, reset/reuse, and clean MEX
teardown.

Generated package classes and the MEX module remain build output:

```text
build/matlab-wrapper/wrap_interfaces/wrap/eklt_rebuild/
build/matlab-wrapper/wrap_interfaces/wrap/eklt_rebuild_mex/
```

Adding `--install` also performs the normal prefix-relative native installation
and lets the inherited helper materialize its merged local toolbox below
`wrap_interfaces/matlab/`. Shared builds co-locate the exact
`libeklt-rebuild` target artifact and resolve it through `$ORIGIN` on Linux or
`@loader_path` on macOS; static installs remove that exact prior runtime and
need only the MEX module. Unrelated files are never scanned or removed. The
generated directory is ignored, and generated classes and binaries are
excluded from source packages.

The build resolves MATLAB explicitly from `/usr/local/MATLAB/R2024b`. Override
only the root, while keeping R2024b, with `EKLT_MATLAB_ROOT`.

## Required runtime preload

MATLAB must be started with the system `libgcc_s` and `libstdc++`. Use the
existing workstation launcher that provides this preload, or invoke R2024b
directly:

```bash
LD_PRELOAD=/lib/x86_64-linux-gnu/libgcc_s.so.1:/usr/lib/x86_64-linux-gnu/libstdc++.so.6 \
  /usr/local/MATLAB/R2024b/bin/matlab
```

For a headless command:

```bash
LD_PRELOAD=/lib/x86_64-linux-gnu/libgcc_s.so.1:/usr/lib/x86_64-linux-gnu/libstdc++.so.6 \
  /usr/local/MATLAB/R2024b/bin/matlab -nodesktop -nodisplay -batch "<command>"
```

Do not run wrapper validation through an un-preloaded `matlab` process.

## Usage

```matlab
addpath("build/matlab-wrapper/wrap_interfaces/wrap/eklt_rebuild")
addpath("build/matlab-wrapper/wrap_interfaces/wrap/eklt_rebuild_mex")

objReconstructor = wrap_adapters.CFibarReconstructorAdapter( ...
    240, 180, uint32(10000), 0.5, true);

dX = double(ui16X(:));
dY = double(ui16Y(:));
dPolarity = double(i8Polarity(:));
dTimestampsUs = double(i64TimestampsUs(:));
objReconstructor.acceptEvents(dX, dY, dPolarity, dTimestampsUs);

dImage = objReconstructor.requestImage(i64TimestampsUs(end));
objPatch = objReconstructor.requestPatch(50, 50, 5, i64TimestampsUs(end));
dPatchIntensity = objPatch.intensity();
dPatchValidMask = objPatch.validMask();
```

The Eigen array API intentionally accepts double column vectors in MATLAB.
The adapter rejects fractional, non-finite, out-of-range, or unequal-length
event arrays before passing exact integer buffers to the ROS-free core. Batch
validation is atomic.
